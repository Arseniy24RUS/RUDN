# Безопасность и ограничения

## Модель доступа

Студентская сессия использует Firebase Anonymous Authentication. Номер студенческого билета или корпоративный email выступает логическим идентификатором учебного профиля, а не криптографическим удостоверением личности. По принятому преподавателем решению студент входит без пароля или кода восстановления, в том числе на новом устройстве. Знание чужого номера позволяет подключиться к соответствующему профилю; такую модель нельзя считать строгой аутентификацией личности.

Полный групповой журнал доступен только преподавателю. Индивидуальный профиль можно прочитать по его ключу для входа, а попытки и оценки — из Firebase UID, подключённого к этому профилю. Преподавательский доступ определяется Firebase-учётной записью `omnistat@yandex.ru`. Storage ограничивает размер файла 12 МБ и путь владельца.

В версии 1.2 повторная отправка оценки допускается из нового подключённого UID, но только с точным баллом и активностью существующей неизменяемой попытки того же студента. Снижение оценки и удаление попытки студентом запрещены; `recordGrade:false` и аудиторный квиз исключены из студенческой записи оценок. Изменение правил не переносит и не перезаписывает рабочую базу.

Черновики и очередь отправки сохраняются раздельно по студентам на устройстве и не удаляются при выходе. На общем устройстве следует учитывать, что локальные данные доступны владельцу браузерного профиля. Кэш преподавательского журнала удаляется при выходе; для работы без сети он доступен только ранее вошедшему преподавателю. Первый вход требует Firebase Authentication; автономного обхода пароля нет.

## Дополнительные номера студенческих билетов

В версии 1.2.2 `rudn-platform/v1/studentAliases/<дополнительный номер>` указывает на существующий неизменный `studentKey`. Оба номера и соответствующие адреса `@rudn.ru`/`@pfur.ru` открывают один профиль. Попытки, оценки, владельцы Firebase UID, черновики и очередь не переносятся между ключами. Старый номер остаётся основным идентификатором профиля.

Добавлять соответствия может только преподаватель. Правила запрещают ссылку на отсутствующий профиль, цепочки соответствий, замену уже существующего профиля соответствием и создание студентом дубликата по дополнительному номеру. Перед добавлением требуется проверить ФИО и отсутствие отдельного профиля по новому номеру. При конфликте нельзя молча объединять результаты. Неизвестный номер при недоступной базе не регистрируется; ранее проверенное соответствие можно использовать с локальным кэшем профиля.

## Что нельзя защитить на чистом GitHub Pages

Статический клиент не может скрыть правильные ответы и не может надёжно доказать, что результат сформирован неизменённым браузерным кодом. Заинтересованный пользователь способен изменить JavaScript или отправить запрос самостоятельно. Для высокозначимого итогового контроля понадобится серверная проверка ответов — например, Cloud Functions/Cloud Run или отдельный API.

## Персональные данные

Платформа обрабатывает ФИО, корпоративный адрес, номер студенческого билета, группу и учебные результаты. Перед эксплуатацией на реальном потоке следует определить оператора, правовое основание, сроки хранения, порядок удаления и допустимую территорию размещения данных. GitHub Pages и стандартный Firebase не следует автоматически считать соответствующими внутренним требованиям РУДН или российским требованиям локализации персональных данных.

## Секреты

Firebase web API key является публичным идентификатором проекта; доступ должен ограничиваться Security Rules, App Check и ограничениями ключа. Пароли преподавателя, service-account JSON, private keys и токены GitHub никогда не должны попадать в репозиторий.
