# Развёртывание на GitHub Pages

## 0. Что уже подготовлено

Репозиторий рассчитан на адрес:

```text
https://arseniy24rus.github.io/RUDN/
```

Каталог `site/` содержит статическую версию платформы, а `.github/workflows/deploy-pages.yml` — готовый workflow публикации через GitHub Actions.

## 1. Локальная проверка

На Windows запустите `preview_windows.bat`. Платформа откроется по адресу `http://127.0.0.1:8765/`.

## 2. Загрузка в репозиторий

Самый простой способ на Windows — дважды щёлкнуть:

```text
publish_to_github.bat
```

Или запустить из PowerShell:

```powershell
./publish_to_github.ps1
```

Сценарий:

1. проверяет наличие обязательных файлов;
2. инициализирует Git;
3. привязывает `origin` к `https://github.com/Arseniy24RUS/RUDN.git`;
4. создаёт коммит;
5. отправляет ветку `main`;
6. при установленном и авторизованном GitHub CLI автоматически включает GitHub Pages в режиме GitHub Actions.

При первом `git push` GitHub может открыть браузер для входа или запросить авторизацию через Git Credential Manager. Пароль или токен в файлы проекта не записывается.

### Когда GitHub CLI отсутствует

Файлы всё равно будут отправлены. После этого один раз откройте:

```text
Repository → Settings → Pages → Build and deployment → Source → GitHub Actions
```

Push в `main` запускает workflow автоматически. Его состояние отображается на вкладке **Actions**.

## 3. Firebase для общего журнала и live-квиза

Без Firebase статический сайт открывается и позволяет знакомиться с курсом и выполнять задания в локальном режиме браузера. Для единого электронного журнала, синхронизации между устройствами, преподавательской панели, live-квиза и загрузки подтверждений нужна первоначальная настройка Firebase.

Для проекта `russian-regions-puzzle` уже включены:

```text
Anonymous
Email/Password
```

Правила из `firebase/database.rules.json` и `firebase/storage.rules` опубликованы, а Storage-бакет создан в регионе `US-EAST1`. Создайте преподавательскую учётную запись:

```text
omnistat@yandex.ru
```

Anonymous Authentication и Email/Password не требуют добавления домена GitHub Pages в Authorized domains. Эта настройка понадобится только при подключении провайдеров с перенаправлением, например Google Sign-In.

Для повторного развёртывания правил на Windows запустите `configure_firebase.bat`. Эквивалентные команды вручную:

```bash
npx firebase-tools@latest login
npx firebase-tools@latest deploy --project russian-regions-puzzle --config firebase/firebase.json --only database,storage
```

При выборе проекта укажите действующий проект `russian-regions-puzzle` либо отдельный новый Firebase-проект для платформы. Если используется новый проект, замените `firebaseConfig` в `site/assets/js/config.js`.

Рекомендуется сначала развернуть правила на тестовом проекте и проверить вход тестового студента и преподавателя.

## 4. Итоговая проверка

1. Откройте `https://arseniy24rus.github.io/RUDN/`.
2. Зарегистрируйте тестового студента.
3. Пройдите один лекционный тест и проверьте запись результата.
4. Войдите преподавателем и откройте электронный журнал.
5. Создайте live-сессию Семинара 1 и подключите второй браузер или телефон.
6. Проверьте пазл и начисление 3/4/5 баллов.
7. Проверьте загрузку небольшого изображения в Семинаре 6.
8. Переключите русский, английский и китайский языки.

## 5. Сохранность данных

Обновление GitHub Pages не удаляет данные Firebase. Перед изменением структуры базы или Security Rules экспортируйте Realtime Database и Storage.

## 6. Архитектурное ограничение GitHub Pages

GitHub Pages обслуживает статические HTML/CSS/JavaScript-файлы и не запускает Python/FastAPI. Поэтому серверные функции перенесены в Firebase и клиентскую логику. Правильные ответы, находящиеся в статическом банке вопросов, нельзя считать секретными. Для защищённого экзаменационного контроля потребуется доверенный серверный обработчик.
