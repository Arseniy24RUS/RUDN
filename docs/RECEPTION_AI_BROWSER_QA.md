# Проверка интерфейса «Приёмной» в локальном браузере

Сценарий поддерживает полный банк версии 3 и прежние пилотные досье. Для полного банка дополнительно заполняются поля вывода из фактов, реквизитов и применения нормы, календарных правил, извлечения сведения из выбранного источника и оценки суждения. Правильные ответы браузерному тесту не передаются. Сворачиваемые разделы открываются перед взаимодействием, а выбранный фрагмент проверяется в предварительном просмотре.

После первого решения проверяется отдельное продолжение дела: переписка и первоначальный ответ уже зафиксированы, итог ещё не показывается, переход к следующему делу недоступен. Браузер выбирает контрольное действие и только после его подтверждения ожидает разбор. DOM-сценарий дополнительно проверяет изменение порядка действий кнопками, восстановление вложенных полей черновика, сохранение контрольного выбора и идемпотентный повтор после потери ответа сервера.

Для полного банка DOM-сценарий отдельно отправляет частично заполненное решение через обычное финальное подтверждение. Пустые поля сохраняются как неотвеченные задания и передаются серверу для оценивания; интерфейс не принуждает угадывать пропущенные ответы. Такая проверка не меняет требования к прежним пилотным досье.

## Подготовка публикации

В рабочем семинаре переключатель для ученика отсутствует. Значение `enabled` в `site/apps/reception/ai/config.js` оставляет действующую игру доступной до готовности облачного сервиса. Локальный стенд открывает новый чат независимо от этой настройки.

Функция `receptionApi` использует `gpt-6-luna` через Responses API. Ключ хранится в Firebase Secret Manager под именем `RUDN_RECEPTION_OPENAI_KEY`. Каталог загружается из отдельной локальной папки `private-data/cases` скриптом `scripts/reception-ai-seed.mjs`. GitHub Pages обслуживает клиентские файлы, Firebase Functions — обращения к модели. Доступ к закрытым досье со стороны браузера запрещают правила RTDB.

Для выпуска сначала проверьте URL функции, CORS, получение Firebase ID token, закрытый каталог и запись результата тестовой смены на отдельном Firebase-проекте. Затем согласуйте переключение клиентского `enabled` и серверного `receptionAI/config/enabled` с окончанием активных старых смен. После включения серверной настройки студент не может записать оценку `seminar-5` из старой версии игры. Начатые локальные черновики старой игры не преобразуются в чат-сессии. Проверьте доступность OpenAI API для места проведения занятия перед активацией.

## Запуск

В первом терминале из корня репозитория запустите сервер, указав реальный путь к приватным сценариям вне публичной папки `site/`:

```bash
node scripts/reception-ai-dev.mjs --cases /absolute/path/private-data/cases --provider mock --port 8787
```

Во втором терминале запустите браузерную проверку:

```bash
node scripts/test-reception-ai-browser.mjs --url http://127.0.0.1:8787
```

Нужны Node.js 20 или новее, пакет Playwright и установленный браузер Chromium, соответствующий используемой версии Playwright. Если Playwright уже находится в отдельном окружении Codex, передайте путь к его модулю:

```bash
node scripts/test-reception-ai-browser.mjs \
  --url http://127.0.0.1:8787 \
  --playwright-module /absolute/path/node_modules/playwright/index.mjs
```

Если зависимости ещё нет, её можно установить в отдельную временную папку, сохранив зависимости самой платформы:

```bash
mkdir -p /tmp/rudn-reception-browser-tools
npm install --prefix /tmp/rudn-reception-browser-tools playwright
/tmp/rudn-reception-browser-tools/node_modules/.bin/playwright install chromium
node scripts/test-reception-ai-browser.mjs \
  --playwright-module /tmp/rudn-reception-browser-tools/node_modules/playwright/index.mjs
```

Для WebKit установите соответствующий браузер Playwright и передайте `--browser webkit`. При необходимости `--executable` задаёт путь к уже установленному браузеру, `--headed` показывает окно браузера, а `--out` выбирает папку результатов. Все параметры перечислены в `--help`.

## Что проверяет сценарий

В новом браузерном контексте создаётся учебная сессия без выбора старой/новой версии и без переключателя режима. Локальная страница для проверки использует одно дело; рабочая платформа выбирает контекст занятия автоматически. До отправки первого вопроса проверяется, что сервер сообщил `provider: "mock"`; при другом значении тест останавливается, не отправляя вопрос модели.

Затем проверяются стартовая реплика, настоящий портрет из игровых ресурсов, время сообщений, временная отправляемая реплика и индикатор набора текста. Для наблюдения ожидающего состояния тест удерживает один локальный запрос: статус «отправлено» не должен появиться раньше ответа сервера. Проверяются получение и открытие документа, безопасные ссылки на нормативные источники и доступность разговора из рабочей области. Переход к документам и восстановление истории не должны повторно анимировать старые сообщения.

Сценарий заполняет черновик решения произвольными допустимыми значениями, сохраняет неотправленный вопрос и перезагружает страницу. Проверяется восстановление той же сессии, отсутствие дублирования отправленных вопросов, сохранность выбора и текста. Переключение русского, английского и китайского языков также должно сохранять черновик. На всех трёх языках проверяется отсутствие технических обозначений ИИ, модели, провайдера и элементов выбора прежнего режима в видимом интерфейсе.

Телефонная часть проверяет ширину **320, 360 и 390 CSS-пикселей**. На каждом размере открываются разговор, документы, источники и решение; проверяются отсутствие горизонтального переполнения, сохранение неотправленного вопроса, обоснования, выбранных ответов и переписки. В разговоре проверяется видимость поля ввода и кнопки отправки; при переходе к материалам разговор остаётся в состоянии приложения и скрывается визуально. Кнопки, поля, select, раскрываемые заголовки и кликабельные подписи radio/checkbox должны иметь область нажатия не меньше 44 × 44 CSS-пикселей. Обычные текстовые ссылки в эту проверку не входят.

Дополнительно используется короткий viewport **390 × 460**, чтобы выявлять перекрытие поля ввода и кнопки отправки. Такое уменьшение окна **не имитирует физическую клавиатуру телефона** и не проверяет поведение IME, автокоррекции, браузерной адресной строки или изменения `visualViewport` на настоящем iOS/Android. Их следует проверить на устройстве перед занятием.

Проверка `prefers-reduced-motion` ожидает остановки видео персонажа и отключения декоративной анимации нового сообщения. Подтверждение решения, серверный разбор и завершение выполняются на размере телефона 390 × 844; проверяется статус `journalStatus: "local"`. Тест не пытается получить 100 баллов: он проверяет обработку решения и отображение результата, а не знание правильных ответов.

Внешние нормативные сайты не посещаются: проверяются ссылки и их атрибуты. Полнота и загрузка правового корпуса требуют отдельной проверки существующей читалки при доступном источнике.

После исполнения в выбранной или временной папке появляются снимки экранов и `report.json`. При ошибке отчёт содержит название неудачного этапа; снимок ошибки создаётся только если браузер действительно успел открыться. Отчёт со значением `"status": "passed"` появляется исключительно после завершения всех проверок. Отмена загрузки WebM с `net::ERR_ABORTED` при остановке персонажа записывается отдельно как ожидаемая отмена ресурса; остальные сетевые ошибки сохраняют статус ошибки проверки.

## Проверки без браузера

```bash
node --test firebase/functions/reception-ai/*.test.mjs tests/reception-ai-api-client.test.mjs tests/reception-messenger-media.test.mjs
node --check scripts/test-reception-ai-browser.mjs
```

API-клиент проверяется отдельно: обновление Firebase ID token должно сохранить идентификатор запроса, потерянный сетевой ответ не должен запускать автоматический повтор, а внутренние диагностические сообщения не должны показываться студенту.

Исполнимая DOM-проверка `scripts/test-reception-ai-dom.mjs` также пройдена в среде подготовки. Проверены ожидающая реплика, подтверждение отправки после ответа сервера, индикатор набора, метки времени, анимация только новых сообщений, сохранение одного video-узла при перерисовке, восстановление черновика и переписки, локализация и отсутствие технических ярлыков. Отдельно проверяется состояние телефонной панели `mobilePane`, переходы разговор → документы → источники → решение → разговор и восстановление выбранной панели после перезагрузки. Проверен и штатный вход `ai/entry.js`: контекст занятия с разрешённым оцениванием сразу начинает самостоятельную смену из восьми дел, получает токен через backend и не читает черновики прежнего движка. Для видео используются заглушки декодера jsdom; реальное воспроизведение и геометрия CSS такой проверкой не подтверждаются.

```bash
npm install --prefix .reception-ai-local/qa-deps --no-audit --no-fund --ignore-scripts jsdom@26.1.0
node scripts/test-reception-ai-dom.mjs --cases /absolute/path/private-data/cases --jsdom .reception-ai-local/qa-deps/node_modules/jsdom/lib/api.js
```

Установка QA-зависимости не изменяет package.json платформы. Модульные проверки медиа дополнительно проверяют сохранение источника и позиции видео при перерисовке, остановку при скрытой вкладке и уменьшенном движении, отказ проигрывателя и освобождение ресурсов.
