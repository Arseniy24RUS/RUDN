# Обновление снимка вакансий

`scripts/sync-career-vacancies.mjs` получает публичную выдачу портала Госслужба без входа и сохраняет локальные JSON для компонента профориентации. Это не backend и не обращение от имени студента. Скрипт не откликается на вакансии, не подписывается на рассылки и не отправляет персональные данные.

## Ручная команда

В корне репозитория, Node.js 20 или новее:

```sh
node --test tests/career-vacancy-sync.test.mjs
node scripts/sync-career-vacancies.mjs --check
node scripts/sync-career-vacancies.mjs --refresh --evidence evidence/runs/manual-career-vacancy-sync
node scripts/sync-career-vacancies.mjs --check
```

Для каждого запуска указывайте новый каталог evidence. Первая и последняя команды проверки работают без сети. `--check` не запускает обновление и не принимает дополнительные параметры. Обновление пишет только `site/apps/career/data/vacancies/gossluzhba.json`, `sync-status.json` и указанный каталог evidence. Само по себе оно ничего не публикует.

Если уже получен и проверен архив последнего опубликованного выпуска, можно сохранить более свежий снимок из этого архива при недоступности источника:

```sh
node scripts/sync-career-vacancies.mjs --refresh --baseline /absolute/path/to/platform-baseline
```

В режиме `--baseline` ресурс находится через `release.json`, manifest и `platform-baseline.json`; проверяются его размер и SHA-256. Для legacy-архива проверяется обычный путь ресурса. Неизвестные пути за пределами архива отвергаются.

## Источник и область покрытия

Контракт непосредственно прочитан из публичных JS портала 27 октября 2026 года:

- Поиск: `POST https://gossluzhba.gov.ru/api/vacancy/data/get-vacancies`. Это чтение выдачи с телом фильтра, а не публикация или отклик.
- Карточка: `GET https://gossluzhba.gov.ru/api/vacancy/data/{UUID}`.
- Фильтр: `showFederal:true`, `applicationHasExpired:false`, `isTargetedTraining:false`, `isElectronicResponseEnabled:false`; все регионы, сортировка по дате объявления, по 100 записей на странице.
- Получаются все страницы именно этого фильтра. Он не представляет весь портал, все уровни власти или полный справочник работодателей.

Лимиты: 50 страниц, 500 групп работодателей, 750 индивидуальных карточек центральных органов, 1 200 запросов на запуск. Запросы последовательны, интервал между началами не меньше 450 мс, таймаут каждого — 25 секунд. Авторизация, cookies, перенаправления и любые другие API endpoints запрещены кодом. При HTTP-ошибке, HTML вместо JSON, изменении контракта, дубликатах, изменившемся числе страниц или превышении лимита обновление прекращается. Обход CAPTCHA и сетевых ограничений не выполняется.

## Сопоставление и смысл полей

Имена сравниваются точно после нормализации пробелов, регистра, `ё` и написания «Российская Федерация»; поиск по подстроке или похожести не применяется. UUID берутся исключительно из `organizations` официальной карточки. Это ссылки на записи внутри объявления, а не подтверждённые канонические ID ведомств: один работодатель может иметь разные UUID в разных объявлениях. Поле `idScope` сохраняет эту границу. `sourceEmployerCount` считает точные имена, `sourceReferenceCount` — исходные ссылки; эти числа не подменяют друг друга.

Для каждого объявления центрального органа индивидуально проверяются исходная ссылка на работодателя, его имя, статус и образование. Даже одноимённые записи с разными UUID сохраняются отдельно. Территориальная связь допускается только при исходном `subTypeName: "Территориальный орган"` и подтверждённой иерархии, однозначно связанной с каталогом. Подведомственное учреждение не становится территориальным органом из-за похожего названия.

Для остальных работодателей одна карточка подтверждает исходную ссылку и иерархию группы с точным именем источника. В каждом объявлении сохранены способ связывания и ссылка на свидетельство. Поле `sourceOrganizationReference` у объявления остаётся `null`, если его собственная ссылка не наблюдалась; `organizationId` в таком случае служит только локальному объединению группы по имени. Это ограничение не скрывается как индивидуальное подтверждение всех UUID. Статус и образование одной карточки никогда не копируются в соседнюю. Неизвестные связи остаются `unmapped` и не попадают в личную подборку.

Дата публикации сохраняется отдельно от начала приёма: `acceptFrom` не выводится из неё автоматически. Строки источника вида `2026-11-26T00:00:00` сохраняются как календарная дата `2026-11-26`. Неизвестные или неоднозначные даты отвергаются. Если срок или статус отсутствует, интерфейс предлагает уточнить приём на официальном портале. Отсутствие объявления в снимке не доказывает отсутствие вакансий в организации.

## Ошибка источника и публикация

Сетевой сбой возвращает `status: unavailable`, сохраняет последнюю успешную копию и её `lastSuccessAt`, а причину записывает в `sync-status.json`. Эта ожидаемая недоступность не должна выключать учебный курс. Структурная ошибка локальных файлов или контрольной проверки даёт ненулевой exit code.

Снимок включается в новый immutable release как обычные ресурсы `apps/career/data/vacancies/*.json`. Уже открытый выпуск продолжает использовать свои закреплённые ресурсы; «Проверить обновление копии» не обходит manifest и не вызывает внешний API. `entry.mjs` сохраняет `liveVacancies:false`.

Автоматическое обновление подключено в `.github/workflows/deploy-pages.yml` с явного разрешения пользователя от 27 октября 2026 года. Перед загрузкой baseline выполняются тесты загрузчика и проверка текущего снимка без сети. После получения последнего опубликованного baseline и до сборки immutable release обычные push, schedule и workflow_dispatch запуски обновляют снимок. Pull request и focused hotfix не обращаются к порталу. При запуске только для проверки обновление выполняется в сборке, но правила запрета публикации сохраняются.

Используется существующее ежедневное расписание: 04:23 UTC, то есть 07:23 по Москве. GitHub может начать плановый запуск с задержкой. Расписание, права workflow и условия публикации не изменены. При недоступности портала сохраняется последняя успешная копия, включая более свежую из опубликованного baseline.

Изменение подготовлено локально; оно начнёт выполняться после попадания в основную ветку GitHub. В рамках подключения ни публикация, ни ручной запуск workflow не выполнялись. Предварительное предложение и причина первоначального отказа автоматической проверки сохранены как историческое свидетельство в `evidence/runs/20261027-vacancy-source-audit/CI_PROPOSAL_REVIEW_ONLY.md`.
