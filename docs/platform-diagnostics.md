# Диагностика платформы v2

Диагностика работает автоматически в фоне: студенту не нужно нажимать кнопку, заполнять форму или сообщать модель телефона. Она помогает сопоставить ошибки разных модулей с версией приложения, браузером и сеансом работы. Отказ отправки диагностики не блокирует задания, оценки и сохранение черновиков.

## Преподавателю

1. В панели преподавателя откройте **«Диагностика платформы»** (`#diagnostics`; EN: **Platform diagnostics**, ZH: **平台诊断**). Из строки студента в журнале можно сразу перейти к его диагностике.
2. Введите фамилию в поле **«Фамилия»** и при необходимости **«Группа»**, нажмите **«Найти»**. Поддерживается начало слова имени; точный номер студента тоже принимается. Справочник содержит имя и группу, но просмотр диагностики не загружает оценки или полные профили.
3. Нажмите **«Открыть»** у студента. Таблица **«Сессии»** показывает начало, код сессии, браузер, доступные сведения об устройстве и сборку. **«Установка браузера»** оставляет сеансы данного экземпляра хранилища; **«Вся история»** над таблицей снимает этот фильтр. Верхняя кнопка **«Вся история»** возвращает общую выборку.
4. Используйте фильтры **«Сборка»**, **«Браузер»**, **«Модуль»**, **«Код»**, **«Начало сессии: с / по»** и **«Применить»**. Например, браузер `safari`, код `target-missing`. Фильтры действуют на сервере по всей выбранной истории. Даты ограничивают серверное время начала сессии, а не время отдельной ошибки. **«Следующие»** и **«Предыдущие»** переключают страницы; пустая страница с продолжением ещё не означает конец выборки.
5. Откройте сессию: **«Сведения о сессии»** содержат характеристики среды, **«Технические сведения»** у события — безопасные подробности. События имеют отдельную пагинацию. **«Выгрузить сессию»** скачивает потоковый JSONL/NDJSON; последняя строка `kind=complete` подтверждает полноту файла. **«Статистика»** тоже считается страницами: промежуточные числа помечены как неполные.

**«Архив без привязки»** содержит сохранившиеся записи прежней версии. Их нельзя достоверно отнести к студенту: один старый Firebase UID мог использоваться с несколькими профилями. Уже перезаписанные прежним кольцевым буфером записи восстановить невозможно.

Поиск, чтение, экспорт и удаление доступны только преподавателю. Обычный студент не получает преподавательского доступа через интерфейс либо прямой запрос.

## Какие сведения доступны

- Сборка, модуль, язык, технические идентификаторы экрана, вопроса, документа и операции; длительность, результат операции и ограниченные числовые показатели.
- Браузер, версия и движок; заявленная ОС, её версия и источник сведений; модель, только если браузер явно предоставил её через стандартные UA Client Hints. Неизвестные значения остаются пустыми.
- Размеры экрана и окна, масштаб и положение visual viewport, плотность пикселей, тип ввода и режим отображения. При доступности — заявленные число логических процессоров, память, параметры соединения, оценка квоты/занятого хранилища и наличие стандартных API. Это сведения браузера, без GPU-проб и вычисления отпечатка устройства.
- Разрешённый код и класс ошибки, уровень важности, до пяти координат собственного JavaScript-кода: путь без query/hash, строка и столбец. `errorClass` ограничен стандартными классами JavaScript, `DOMException` и `FirebaseError`; произвольные имена исключений не принимаются.

В события не записываются ответы, поисковые запросы, выделенный текст, ФИО, номера студентов, оценки, токены, полный URL, исходный User-Agent, сообщения исключений и тела сетевых запросов. Имя/группа нужны отдельному преподавательскому справочнику; связь с учебным профилем хранится в серверных метаданных сессии. Клиент очищает поля, сервер повторно проверяет разрешённую схему.

Идентификатор установки — случайный идентификатор браузерного хранилища. Разные браузеры на одном телефоне могут иметь разные установки; очистка хранилища создаёт новую. Safari может сообщать замороженную версию ОС. По размерам экрана и косвенным признакам модель iPhone не вычисляется. Эти данные помогают локализовать сбой, но сами по себе не подтверждают нагрев или неисправность физического устройства.

## История, владелец и доставка

Принятая сервером история хранится **без автоматического срока**, не вытесняется новыми сеансами и не сокращается из-за лимита пакетов. Удаление — действие преподавателя: **«Удалить эту сессию»**, **«Удалить историю студента»** либо **«Удалить всю историю»**, затем предпросмотр и **«Подтвердить удаление»**. Общее удаление включает непривязанный архив. Большая задача выполняется частями; **«Продолжить удаление»** доводит её до сообщения **«Удаление завершено»**. Профили, оценки и учебные черновики сохраняются.

Сервер закрепляет сессию за Firebase UID и проверенным каноническим `studentKey` с учётом владельцев профиля и alias. Смена профиля даже при прежнем UID создаёт отдельную сессию. События до выбора профиля остаются анонимными и не приписываются студенту задним числом; при первой отправке их UID фиксируется до сетевого запроса. Преподаватель имеет отдельный тип сессии. Эта привязка использует существующую модель входа платформы и не заменяет проверку личности человека.

После удаления сервер меняет `generation` или ставит запрет для удалённой сессии. Поздний запрос и повтор потерянного подтверждения не могут восстановить удалённую историю; новые сеансы следующего поколения принимаются. Служебные признаки удаления остаются для этой защиты.

Локальная очередь ограничена 256 событиями / 256 КиБ; при переполнении ошибки имеют приоритет, потери и объединения повторов учитываются счётчиками. Отправка — до 12 событий / 16 КиБ в пакете, не чаще раза в 30 секунд. Неизменный пакет повторяется с прежним идентификатором: потеря подтверждения не создаёт дубль. Очереди разных профилей изолированы; старый пакет отправляется только под его UID и сохраняет исходную привязку. Очередь и недоступность сети могут привести к потере событий **до приёма сервером**. Фонового опроса экрана нет; скрытие страницы даёт одну допустимую попытку доставки, возврат возобновляет очередь.

## Разработчику модуля

Оболочка передаёт необязательный `diagnostics`, закреплённый за владельцем, модулем и сборкой. Общие обработчики собирают ошибки запуска/ресурсов, необработанные исключения, переходы, сеть и видимость; смысловые ошибки из `catch` и длительности операций должен отмечать сам модуль. Глобальная ошибка без надёжного пути собственного модуля относится к платформе, а не угадывается по открытому маршруту.

```js
const finish = diagnostics?.span('document-load', {docId: 'koap'});
try {
  await loadDocument();
  finish?.({success: true});
} catch (error) {
  finish?.({success: false, code: 'load-failed'});
  diagnostics?.error(error, {operation: 'document-load', docId: 'koap'});
}
diagnostics?.record('document-jump', {
  docId: 'koap', success: true, found: true, visible: true
});
```

Вызовы записи не ожидают сеть. Передавайте технические константы, а не пользовательский ввод. Для самостоятельного входа используйте общий `getSharedPlatformDiagnostics`, затем `forModule(name)`; сохраняйте полученный контекст для отложенной операции. При выходе вызывайте `destroy()` контекста. После смены владельца старые callbacks не получают новую личность.

Полные разрешённые поля и коды — в [серверной схеме](../firebase/functions/diagnostics-schema.mjs), очистка и SDK — в [diagnostics.js](../site/assets/js/diagnostics.js). Развёртывание, миграция архива, API, ограничения экспорта и откат описаны в [серверном руководстве](platform-diagnostics-server.md). Подключение модулей и сохранение при обновлении — в [контракте обновлений](platform-update-contract.md); точная идентификация сборок — в [описании поставки версий](platform-exact-releases.md).

## Проверки

```text
node --test tests/diagnostics-v2.test.mjs tests/diagnostics-cloud-policy.test.mjs scripts/diagnostics-v2-service.test.mjs
node scripts/diagnostics-v2-browser.mjs
firebase emulators:exec --project demo-rudn --config firebase.diagnostics-v2.json --only auth,database,functions "node --test --test-force-exit scripts/diagnostics-v2-emulator.test.mjs"
```

Браузерная проверка использует синтетические данные, RU/EN/ZH, мобильный и настольный размеры в Chromium, Firefox и WebKit. Она проверяет интерфейс и контракт, но не заменяет проверку физических телефонов и не доказывает устранение нагрева конкретного устройства.
