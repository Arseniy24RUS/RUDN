# Точная поставка актуальной версии

Готовая публикация создаётся `scripts/build-platform-release.mjs` после Firebase, Career, Reception и обновления календаря. Исходный `site/` не переписывается генератором. Сборка принимает **фактически опубликованный** архив и новый каталог staging, затем проверяет все опубликованные файлы до загрузки в Pages.

## Политика хранения

В публикации хранится только актуальная версия: `release.json`, manifest и service worker явно содержат `retention: "current-only"`, а `previous` всегда равен `null`. Старые runtime, заменённые объекты и удалённые исходные ресурсы не копируются в новую поставку. Старые архивы GitHub сборщик не меняет.

Эта политика относится к исполняемому коду и статическим ресурсам. Завершённые игры, результаты, оценки и учётные записи не входят в staging и не удаляются сборщиком. Новые игры используют текущую версию. Поддержание незавершённых заброшенных партий на старом коде не является основанием хранить предыдущие сборки и их резервные форматы данных.

* Runtime HTML/JS/CSS: `/_releases/<buildId>/<исходный путь>`. Относительные импорты остаются внутри этой версии. Inline ES-модули HTML становятся соседними сгенерированными `.mjs`.
* Неизменённые данные и медиа могут сохранять первоначальный путь, **только если текущий manifest использует эти же байты**. `platform-baseline.json` хранит их контрольные суммы. Заменённый или удалённый ресурс освобождает прежний путь при следующей сборке.
* Новые и изменённые данные: `/_objects/<полный SHA-256>.<расширение>`. `resourceURL()` сопоставляет логический URL с неизменяемыми байтами, в том числе без service worker. В поставку входят только объекты текущего manifest.
* Build ID вычисляется по конечным runtime-текстам с нормализованным собственным ID, baseline ID, хешам ресурсов и шаблону worker. Верификатор пересчитывает его, проверяет descriptor и хеши всех ресурсов.
* Предельный размер — 1 000 000 000 байт. Учитывается каждый физически опубликованный файл, включая отчёт сборки. Верификатор отклоняет лишние файлы, которые не принадлежат текущему manifest, его lazy-коллекциям, публичным HTML-входам или служебным файлам поставки.

## Переход с замороженной базы

Реестр схемы 3 содержит `retention`, `files` и `legacyEntryHTML`. Политика вместе со списками файлов входит в baseline ID. При переходе со схемы 2 сборщик проверяет её исходный ID, выбирает только используемые текущей версией неизменённые данные и вычисляет новый ID. Старые JS/CSS и HTML-фрагменты из корня базы не сохраняются: их текущие версии публикуются в immutable runtime.

Канонические HTML-адреса игр остаются маленькими alias-страницами. Они читают текущий manifest и открывают соответствующий exact HTML. `legacyEntryHTML` сохраняет только реестр прежних HTML-входов, а не старый код. Верификатор проверяет alias-страницы, текущий `index.html` и корневой `404.html` побайтно.

Исходный архив не изменяется. Сборщик не обещает выдавать старые lazy-ресурсы по удалённым адресам для старого игрового кода. Возврат к игре должен открывать её актуальный вход; уже сохранённые завершённые результаты остаются в штатном хранилище платформы.

## Что не публикуется

`scripts/platform-publication-policy.json` перечисляет точные проверенные пути, исключённые из поставки: исходные материалы локализации Reception, её сборочные скрипты и тесты, тестовые фикстуры контента и недостижимые исторические файлы Settlements v2. Они могут оставаться в Git для воспроизводимости сборки. Общего правила «удалить все документы» или исключения по расширению нет.

Исключения применяются до построения manifest и baseline. Если исполняемый код начнёт импортировать исключённый файл, проверка достижимых ES-импортов завершит сборку ошибкой. Динамические загрузчики данных проверяются тестами соответствующего модуля; отсутствие буквального импорта само по себе не доказывает ненужность ресурса.

## Открытие и проверка версии

В каждом полном HTML встроен небольшой recovery-скрипт без импортов. При холодном открытии устаревшего exact-адреса Pages 404 восстанавливает известный публичный HTML по проверенному **текущему** manifest. Query и hash сохраняются. Временный маркер `rudnRecovery` ограничивает переход одной попыткой и удаляется после запуска. Неизвестный путь остаётся 404; повреждённый текущий runtime не запускает цикл перезагрузок. Этот путь работает без service worker и CacheStorage.

`prepareRelease()` проверяет оболочку и пакет активного модуля до переключения. Флаг `durable` означает возможность записать подготовленный пакет в CacheStorage; он не означает, что загружен весь корпус документов. Версии интеграционных контрактов заданы в `site/data/platform-contracts.json` и включены в `manifest.contracts`. Отсутствующий или некорректный контракт не допускается сборщиком и bootstrap. Автоматического отката к старому опубликованному runtime нет: `previous` отсутствует по политике текущей версии.

Проверка импортов начинается со всех публичных HTML, main и module entry, включает статические ES-импорты, строковые `import()` и `new URL('worker.mjs', import.meta.url)`. Отсутствующая зависимость достижимого приложения блокирует публикацию.

После успешного Pages deploy архив `platform-release-<buildId>.tar.gz`, SHA-256 и receipt сохраняются в GitHub Release; резервный Actions artifact имеет установленный срок хранения. Следующая сборка выбирает входной архив по build ID реально опубликованного `release.json`, а не по самому новому тегу. Архив нужен для восстановления и воспроизводимости; его историческое содержимое не переносится целиком в сайт. При отсутствии архивов сборка завершается ошибкой. Для первой миграции единственный fallback — проверенный Pages run 39135557270; после появления exact pointer этот fallback закрыт.

Проверки сборщика: `node --test scripts/test-platform-release.mjs`. Проверки браузерного протокола и модульных загрузчиков запускаются отдельно по затронутой функциональности. Физические смартфоны — отдельная полевая проверка.
