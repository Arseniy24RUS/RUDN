# «Система расселения» — модуль платформы 1.0

Игра из `RUDN-Settlements-Codex-Production-Kit/game` встроена динамическим импортом и двумя изолированными Shadow DOM. Платформа управляет профилем, доступом к теме 3, назначением территории, журналом и рейтингом. Движок сохраняет действующие цены, мощности и три сложности.

## Поведение

- `#activity/seminar-3`: случайная территория из 82, исключая предыдущую; высокая/средняя/низкая сложность даёт 5/4/3 балла. Сохраняется лучший балл; прежние работы и оценки остаются в базе.
- `#games/settlements`: выбор территории и сложности; результат не меняет журнал. Гости сохраняют игру локально.
- Первое обучение обязательно, использует семь поселений Челябинской области. Повтор доступен из игры и не меняет текущую партию.
- Баллы и рейтинг доступны после завершения при неокруглённом среднем охвате населённых пунктов от 90%. Начальный высокий охват не завершает игру. При четырёх 100% результат фиксируется автоматически; при отсутствии доступных платных действий игрок может выполнить бесплатные соединения или завершить игру.
- Завершённая карта открывается только для просмотра. Незавершённую попытку перед новой явно прекращают. Пока итог не доставлен в базу, следующая попытка не начинается.
- Таблица лидеров разделена по режимам и сложности. Для каждого участника выбран лучший результат: расходы по возрастанию, затем охват НП и населения по убыванию, ходы и время по возрастанию.

Охват населения — среднее четырёх отношений `people / population`, вычисленных движком с учётом доли доступной услуги для жителей каждого поселения. Это отдельный показатель от доли занятых мощностей: например, места в школе не заменяют численность населения в знаменателе рейтинга.

## Хранение

`settlements-storage.js` использует общие `durable-store` и `checkpoint-sync`. Каждое действие и отмена получают новую монотонную ревизию. Сохраняются replay и состояние интерфейса, без геоданных. `engineSave` в RTDB кодируется JSON-строкой: это сохраняет пустой массив действий после отмены. При восстановлении проверяется облачная версия.

Вкладки одного профиля используют общий writer lock для обоих режимов и обучения. Перед передачей сохраняется активное время, новая вкладка восстанавливает актуальную карту. При расхождении устройств записи приостанавливаются; обе ветви сохраняются, продолжение выбирается явно.

Конфликты партии и обучения разрешаются отдельно. Выбор привязан к показанному конфликту, даже если во время ожидания обнаружилась другая ветвь. Пока остаётся хотя бы один конфликт, изменения и фиксация результата заблокированы. Для обучения replay и шаг берутся из выбранной ветви, а уже полученная отметка прохождения сохраняется. Статус сохранения виден непосредственно над картой и различает запись на устройстве, отправку и подтверждение облаком.

Итог доставляется в порядке: подтверждённый checkpoint → неизменяемая attempt → лучший балл → рейтинг. Повторные запросы идемпотентны. Учебные и скрытые интервалы не включаются в время партии.

Области базы внутри `rudn-platform/v1`:

- `checkpoints/<student>/seminar-3`, режим `settlements-assessment`;
- `checkpoints/<student>/settlements-freeplay`, режим `settlements-free`;
- `checkpoints/<student>/settlements-tutorial`, режим `tutorial`;
- существующие `attempts` и `grades` с новым типом `settlements`;
- новые `settlementsOwners` и `settlementsLeaderboard/<mode>/<difficulty>`.

Rules связывают запись рейтинга с владельцем, неизменяемым результатом и завершённым checkpoint. ФИО и группа фиксируются на момент результата; последующее редактирование профиля не блокирует доставку очереди.

## Воспроизводимый перенос

```powershell
node scripts/sync-settlements.mjs --source 'C:\Codex projects\RUDN-Settlements-Codex-Production-Kit'
node scripts/sync-settlements.mjs --check
node --test scripts/test-settlements-contract.mjs scripts/test-settlements-storage.mjs
```

Реестр `site/apps/settlements/source-manifest.json` содержит SHA-256 каждого включённого ресурса и отдельно 576 защищённых исходных файлов. `RUDN-data-cache`, исходные архивы, шрифты и инструменты разработки не публикуются. Каталог не загружает карты. Сцена получает одну территорию; перед следующей прежняя сохраняется и уничтожается. Региональные планы и транспортные данные читаются как данные, без удержания в кеше JS-модулей. Service worker не скачивает регионы предварительно.

Исходные координаты и демографические показатели сохранены. Федеральное дополнение добавляет 45 канонических записей и три исходных полигона к партиям Московской области, Ленинградской области и Крыма. Получается 82 игровые территории с 155 839 записями. Сохраняются авторские обозначения исходных населённых пунктов.

## Публикация и откат

Перед публикацией необходимы свежий полный replay 82 × 3, браузерные проверки текущей сборки и Firebase Emulator. Отчёты со старыми хешами не заменяют проверки нового кандидата. Полевые испытания физических телефонов и реальных студентов остаются отдельным человеческим этапом.

Сначала прочитать только действующие Rules командой Firebase CLI `database:get '/.settings/rules'`, затем сравнить их:

```powershell
node scripts/compare-settlements-rules.mjs --live <rules-only.json> --baseline fa87502283af941d8ed3cc59d8703869aee68869
```

Развёртывать только правила базы (`--only database`), без импорта/перезаписи данных. Кандидат меняет четыре проверенные области Rules; при расхождении других областей сначала согласовать актуальное состояние кода и повторить эмулятор.

Откат сайта: отдельным revert-коммитом отменить коммит интеграции в `main`, затем дождаться GitHub Pages. Не откатывать и не очищать студенческую базу: новые попытки, оценки и рейтинг сохраняются. Добавленные правила можно оставить — старый сайт не обращается к новым узлам. Не восстанавливать старый полный дамп базы. Последующая исправленная сборка продолжает сохранения текущей версии движка.
