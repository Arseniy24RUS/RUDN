# Проверка модуля карт

Каталог формируется из данных приложения командой `prepare_puzzle_catalog.py`.
Каждая запись проверяется отдельно; ошибки источника и пропуски не считаются
успехом. В версии 1.3.7 доступны 288 карт: мир, 198 карт регионов стран
(включая авторскую Россию с 89 субъектами) и 89 муниципальных карт.
Прежний каталог из 289 записей содержал две карты России. Внешняя ADM1 RUS
больше не предлагается для новой игры, но остаётся в данных для восстановления
старых попыток. Аудит источников по-прежнему проверяет все 289 наборов; обычная
браузерная матрица получает 288 выбираемых карт, а историческую Россию проверяет
отдельный тест обновления. В приложении находятся 111 наборов; из внешних
источников доступны 177 выбираемых наборов и один исторический. Исправления
исходных данных описаны в `site/assets/puzzle/data/adm1/SOURCE_REPAIRS.md`.

## Воспроизводимый прогон

Нужны Node.js 20+, Python 3.12, Playwright 1.61.0 и Java 21 для Firebase Emulator.
Артефакты следует сохранять вне каталога репозитория.

```sh
npm ci --ignore-scripts
npm run build:firebase
python -m pip install playwright==1.61.0 openpyxl==3.1.5
python -m playwright install --with-deps chromium firefox webkit
python scripts/prepare_puzzle_catalog.py --output ../puzzle-qa --refresh
python scripts/test_puzzle_catalog.py --output ../puzzle-qa
python scripts/test_puzzle_interactions.py --output ../puzzle-qa
python scripts/test_puzzle_resilience.py --output ../puzzle-qa
npx --yes firebase-tools@15.30.1 emulators:exec --project demo-rudn --config firebase.puzzle.json --only auth,database "node scripts/puzzle_storage_emulator_test.mjs"
```

В CI прогон разделён на 18 заданий (три движка, по шесть частей каталога).
Каждая карта проходится на трёх сложностях: подсказка, размещение каждой детали,
сохранение, автономная перезагрузка и завершение без сети. Всего 2592 прохождения.
Отдельно проверяются 12 размеров и ориентаций каждой карты в каждом движке:
320×568, 360×800, 390×844, 412×915, 768×1024, 1024×1366, 1366×768,
1920×1080 и четыре повёрнутых телефонных профиля — 10368 состояний раскладки
на русском языке. `test_puzzle_locale_layout.py` дополнительно проверяет каждую
карту на английском и китайском во всех этих размерах: ещё 20736 состояний,
всего 31104. Обе матрицы обязательны перед публикацией; отдельный агрегатор
проверяет отсутствие пропусков, повторов и ошибок в языковых результатах.
RU, EN и ZH распределены между прохождениями каждой карты; специальные сценарии
дополнительно проверяют подтверждения и зачётные результаты во всех трёх языках.
Состав новой карты мира одинаков во всех языках. Старые китайские попытки с
дополнительной территорией сохраняют свой исходный состав при восстановлении.

Сервер тестов подменяет только транспорт внешних данных и профиль изолированными
данными. Геометрия берётся из проверенных реальных источников с SHA-256. CSP
запрещает внешние соединения и у страницы, и у service worker. Из игрового движка
тест получает только координаты и состояние: ход проходит через PointerEvent,
а не через изменение счётчика или вызов завершения. Отдельные проверки используют
настоящие события мыши, клавиатуры и эмулируемого касания браузера.

`test_puzzle_report.py` проверяет наличие всех сочетаний карты, движка и сложности,
каждого размещения, восстановления без сети и всех размеров. Pages зависит от
успеха этого задания и `test_puzzle_locale_report.py`. Проверки Firebase используют только `demo-rudn` на
127.0.0.1:9000/9099 и настоящие правила доступа репозитория.

## Границы проверок

- Chromium, Firefox и WebKit — отдельные браузерные движки; это не испытания на
  физических iPhone, iPad или Android. Такие устройства требуют отдельного прогона.
- `test_puzzle_performance.py` запускает установленный Edge и указанный официальный
  Chrome for Testing. Он измеряет интервалы кадров, задержки обработчиков и
  перерисовки, длительные задачи и удерживаемую память после смены тяжёлых карт.
  Нагрузка компьютера влияет на цифры; измерения не являются обещанием FPS телефона.
- У Playwright WebKit обнаружен сбой автономного `page.reload()`
  даже на минимальном service worker без паззла. Его воспроизводит
  `test_puzzle_offline_probe.py`. Для WebKit проверяется разрыв TCP-соединения без ответа сервера;
  перед восстановлением проверяется отказ некэшированного запроса. Этот способ
  явно указан в отчёте и не считается проверкой системного offline WebKit или iOS.
  Chromium и Firefox используют настоящий offline браузера.
- Итоговый отчёт о конкретном прогоне хранится в артефактах CI, а не выводится из
  одного успешного финального экрана. Частичные локальные прогоны не заменяют его.

## Поведение сохранения

Восстановление поддерживается в том же браузере, пока сохранены данные сайта.
Первая загрузка неподготовленной карты требует подключения. Геометрия начатой
карты сохраняется отдельно, поэтому повторное открытие не зависит от доступности
внешнего источника. При отказе всех доступных хранилищ игра продолжается с одним
неблокирующим сообщением о невозможности сохранить прогресс.

Видимая активная игра запускает время первым действием; сворачивание ставит его
на паузу. Завершение фиксирует локальный результат и постоянный attemptId до
доставки оценки и строки лидеров. Повторная доставка использует первоначальные
данные и соблюдает запрет Firebase на перезапись результатов.


## Изменения 1.3.7 и обязательные дополнительные проверки

- `test_puzzle_render_geometry.cjs` проверяет все вершины исходной российской
  топологии: общие границы, невырожденные кольца, неизменность сохранённых данных,
  ошибку не более 0,35 CSS px и ограниченный кэш детализации.
- `test_puzzle_render_browser.py --dpr-checks` проверяет фактические операции
  рисования при DPR 1/2/3, масштабах 1/2/4/8/16, правый лоток в альбомном
  fullscreen, доступные кнопки, перенос детали и сохранение географического
  центра при повороте. Проверки выполняются в RU/EN/ZH. При сравнении Canvas
  допускается не более одного уровня из 255 в alpha и premultiplied RGB каждого
  пикселя: нативное сглаживание может округляться по-разному. Исходные различия
  сохраняются в отчёте; этот допуск не относится к координатам. Сам контроль
  проверяется на изменённом цвете, alpha и удалённом непрозрачном пикселе.
- `test_puzzle_release_upgrade.py` загружает реальный код 1.3.6 из коммита
  `780d787`, создаёт игру через интерфейс, обновляет worker и восстанавливает её
  без сети. Проверяются как авторская Россия, так и прежний внешний набор RUS.
- `test_puzzle_raster_worker.py` сравнивает каждый RGBA-компонент подготовленных
  изображений Канады и Чили с точными исходными контурами, проверяет отмену
  устаревшей подготовки, смену масштаба, ошибку worker и точный запасной способ
  отрисовки в браузерах без поддержки. Кэш активной детали вместе с резервом
  выполняющейся задачи ограничен 16 МиБ, сохранённые и передаваемые команды
  суммарно — 8 МиБ. При новом масштабе worker повторно использует те же точные
  команды; проверяется отсутствие повторной сериализации и отмена старой задачи.
- `test_puzzle_leaderboard_emulator.py` использует действующие правила Firebase
  Emulator и настоящий интерфейс: все 89 деталей, оценки 5/4/3 с подсказками,
  локальная строка до окончания сетевого запроса, доставка без дубликатов,
  свободный результат без оценки, гость и преподаватель, фильтры, более 100
  участников и скачивание XLSX. Отдельный сценарий впервые загружает библиотеку
  экспорта после отключения сервера из кэша service worker. Производственная база
  в тестах не используется.
- `test_puzzle_leaderboard.mjs` и независимый `test_puzzle_xlsx.py` проверяют
  сортировку, однофамильцев, прежние неизменяемые записи, три листа XLSX, полную
  длительность, типы ячеек, Unicode и строки, похожие на формулы.
- `test_puzzle_native_load.py` проверяет тихое восстановление загрузки встроенной
  карты после сетевого сбоя и отмену незавершённой загрузки при уходе со страницы.
- `test_free_module_contexts.mjs` проверяет реальные модули и раздельные черновики,
  повтор, перезагрузку и завершение без изменения учебных оценок.
  `test_games_platform.mjs` проверяет гостевой каталог, маршруты и ограничения
  всех семи лекционных тестов, реальные максимальные результаты и три звезды
  с рамкой, а также уход из модуля до окончания его загрузки.
- `test_puzzle_performance.py --channels chromium --cycles 3 --cpu-rates 1,4,6 --enforce-budgets`
  измеряет фактическое время Canvas-рисования, интервалы кадров, длинные задачи
  и память при перетаскивании, масштабировании и панорамировании. Первый перенос
  начинается из лотка и включает подготовку изображения детали. До измерения
  тест обычными ходами доходит до территории с наибольшим числом вершин,
  чтобы случайный порядок не подменял тяжёлую деталь простой. Отдельно сохраняются
  время подготовки в worker, сериализация команд, первый показ следующей детали
  и состояние кэша перед первым переносом; ожидания готового worker нет.
  JS heap относится к основному потоку; память GPU, native Path2D и процесса
  целиком этим показателем не измеряется. Растровая память контролируется
  отдельным явным бюджетом. CI ограничивает
  P95 интервалов кадров для переноса и панорамирования величиной `50 × √CPU` мс,
  для масштабирования — `100 × √CPU` мс, максимальный интервал при переносе и
  панорамировании и показе следующей детали — `250 × √CPU` мс, длинную задачу
  загрузки — `3000 × CPU` мс.
  Это пороги регрессии на тестовом runner; исходные измерения сохраняются целиком.
  Ограничение CPU является лабораторной моделью, а не измерением телефона.

Эти проверки включены в `puzzle-checks.yml`, от которого зависит публикация Pages.
Отчёты отдельных прогонов хранятся в артефактах Actions; наличие теста в наборе
не означает его успешного прохождения. Итог полного прогона должен подтверждать
отсутствие пропусков и ошибок на конкретном коммите выпуска.

Аппаратные испытания Huawei Mate XT с Яндекс Браузером, обычных Android,
iPhone и iPad требуют доступа к устройствам. Эмуляция размеров, касаний и DPR
не заменяет такие испытания; при отсутствии устройств они отмечаются как
невыполненные. Реальные установленные Edge и Chrome for Testing проверяются
отдельно от Chromium/Firefox/WebKit в Playwright.
