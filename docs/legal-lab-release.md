## Условия публикации

Полные тексты, приложения и историческая редакция проходят содержательную сверку. Контрольная сумма отдельного файла проверяет доставку, но сама по себе не доказывает полноту закона. Протоколы проверки должны различать автоматическую проверку и заключение человека.

После фиксации корпуса выполните `node scripts/build_legal_lab_manifest.mjs`, затем `node scripts/build_legal_lab_manifest.mjs --check`. Полный CI включает прежнюю матрицу платформы, строгую проверку корпуса, оценивания и черновиков, Firebase Emulator Suite с 30 синтетическими участниками, а также Chromium, Firefox и WebKit. Частичный прогон не заменяет полную матрицу.

После зелёного CI сравните опубликованные правила Firebase с сохранённой исходной копией. Изменение должно быть ограничено `live/legalRooms`. Публикуйте только правила Database, затем проверенный модуль штатным GitHub Pages workflow. Не используйте сокращающие CI метки hotfix. На опубликованном адресе отдельно проверьте обновление старого кэша, семинары, два независимых клиента комнаты и доставку результата.

## Откат без удаления оценок

1. Закройте активные комнаты и предупредите ведущего занятия. Не очищайте записи попыток, оценок, профилей или облачных черновиков.
2. Создайте обратный коммит выпуска через обычный pull request. Если требуется вернуть прежнее расположение тем, возвращайте целые описания семинаров со стабильными идентификаторами. Не перенумеровывайте сохранённые попытки.
3. Задайте новую версию кэша в `site/service-worker.js`, чтобы браузеры получили откат. Повторное использование прежнего имени кэша может оставить смесь ресурсов.
4. Пропустите обратный коммит через CI и штатную публикацию Pages. Сохраните Legal Lab и его версию корпуса в Git для чтения уже созданных отчётов. При точечном отключении оценивания оставьте чтение и экспорт результатов.
5. Верните только прежнюю ветку правил `live/legalRooms`, если она требует отката. Не заливайте всю старую базу и не перезаписывайте параллельные изменения правил. Исходные правила и их контрольная сумма находятся во внутренних доказательствах выпуска.
6. Проверьте старый квиз, новые отчёты, журнал и черновики. Баллы остаются под `activitySlug: seminar-4`, максимум — пять. Откат интерфейса не означает удаление данных новой работы.

Пароли, токены, `.env`, `auth.json`, персональные данные студентов, кэши браузеров и файлы шрифтов в ZIP выпуска не включаются.
