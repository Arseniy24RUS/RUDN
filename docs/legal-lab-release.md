## Условия публикации

Полные тексты 14 действующих актов и их приложения проходят содержательную сверку. Контрольная сумма отдельного файла проверяет доставку, но сама по себе не доказывает полноту закона. Протоколы проверки должны различать автоматическую проверку и заключение человека.

После фиксации корпуса выполните `node scripts/build_legal_lab_manifest.mjs`, затем `node scripts/build_legal_lab_manifest.mjs --check`. Полный CI включает прежнюю матрицу платформы (в том числе 246 сценариев текущего движка расселения), строгую проверку корпуса, оценивания и черновиков, Firebase Emulator Suite с 30 синтетическими участниками, а также Chromium, Firefox и WebKit. Частичный прогон не заменяет полную матрицу. В replay исторический авторский список сохраняется как источник, его цена проверяется отдельно. Исполняемый путь использует нынешние ограничения: нужные дороги и клиники, допустимое разбиение маршрутов и строительство вышек. Промежуточное ребро дороги может ещё не давать услугу; такие шаги отмечаются явно, а полезность проверяется для всего исходного намерения. Итоговые 100% по четырём услугам, бюджет, сохранение, replay и отмена остаются обязательными. Это привилегированный синтетический маршрут, не измерение поведения студентов.

После зелёного CI сравните опубликованные правила Firebase с сохранённой исходной копией. Изменение ограничивается временными ответами `live/legalPresence` и закрытыми привязками `live/legalPresenceOwners`; прежняя ветка `live/legalRooms` закрыта без удаления данных. Совместная запись разрешена только для основных текстовых заданий Q01–Q38; реквизиты, виды актов и досье не публикуют ответы. Ключ преподавателя проверяется отдельно: студентский DOM его не содержит, переход по основанию не создаёт общую отметку. Публикуйте только правила Database, затем проверенный модуль штатным GitHub Pages workflow. Не используйте сокращающие CI метки hotfix. На опубликованном адресе отдельно проверьте обновление старого кэша, семинары, два независимых клиента автоматического совместного режима, исчезновение отметок при уходе и доставку результата. Для сканов проверьте все реквизиты, соответствие цветов названиям, скрытые по умолчанию подсказки и отсутствие отдельного перехвата жеста масштабирования. Проверка политики жестов не считается испытанием масштабирования на физическом телефоне.

## Повторная публикация мобильных исправлений

Владелец разрешил публикацию проверенных исправлений для испытания на телефоне до завершения полного CI. Workflow `legal-lab-phone-test.yml` проверяет точные Git trees приложения, правил и тестов; перед публикацией pins обновляются только на независимо просмотренный кандидат. Обычный полный CI продолжает работать отдельно. Предварительная публикация не означает прохождение всех выпускных критериев.

После изменений чтения проверьте 14 групп документов и все 38 стабильных Q ID, поиск списком поверх текста с закрытием при переходе, прокрутку текста внутри листа и страницы по краям, точные подписи выбранных частей и отсутствие утечки ключа преподавателя. Новые самостоятельные работы записывают `evidenceMode: whole-article-v1`; отсутствие метки сохраняет первоначальный расчёт и строгую проверку старого отчёта. Не добавляйте метку завершённым попыткам. Отдельная звезда квиза не создаёт новую оценку курса.

## Совместимость прежних работ

Новые работы используют `five-task-v1`: пять обычных заданий с максимумом пять баллов. Доступ открывается после отправки всех 52 ответов квиза, независимо от правильности; заработанный допуск сохраняется. Первая новая работа назначается одинаково на устройствах одного профиля, повторная попытка получает другой случайный вариант и новый идентификатор. Завершённые старые работы и их правила оценивания не переписываются.

Удалённые дополнительные ситуации и два неиспользуемых акта отсутствуют в публичном каталоге. Их полные исходники и переводы сохранены только как исторические тестовые доказательства. Если студент раньше ошибочно выбрал такой акт, отчёт использует отдельный проверенный индекс идентификаторов без текста документа. Он сохраняет прежний ответ и расчёт, не добавляется в библиотеку или кэш действующих актов и не позволяет принять подменённый балл.

## Откат без удаления оценок

1. Попросите участников выйти из модуля и предупредите ведущего занятия. Не очищайте записи попыток, оценок, профилей или облачных черновиков.
2. Создайте точечный обратный коммит через обычный pull request. Сохраните исправление восстановления резервных сохранений в общем `durable-store.js`: оно нужно для прежних работ других модулей и не зависит от включения Legal Lab. Если требуется вернуть прежнее расположение тем, возвращайте целые описания семинаров со стабильными идентификаторами. Не перенумеровывайте сохранённые попытки.
3. Задайте новое имя кэша в `site/service-worker.js`, чтобы браузеры получили откат. Для отдельного выпуска Legal Lab меняйте суффикс модуля; базовая версия платформы должна совпадать с `?v=` адресами её JS-файлов. Изменение только базовой версии при прежних адресах блокирует их загрузку защитой от смешения выпусков. После изменения проверьте перезагрузку расселения и пазла с активным service worker. Повторное использование прежнего имени кэша может оставить смесь ресурсов.
4. Пропустите обратный коммит через CI и штатную публикацию Pages. Сохраните Legal Lab и его версию корпуса в Git для чтения уже созданных отчётов. При точечном отключении оценивания оставьте чтение и экспорт результатов.
5. Откатывайте только изменённые ветки правил `live/legalPresence` и `live/legalPresenceOwners`, если это необходимо. Старые комнаты не нужны интерфейсу нового режима. Не заливайте всю старую базу и не перезаписывайте параллельные изменения правил. Исходные правила и их контрольная сумма находятся во внутренних доказательствах выпуска.
6. Проверьте старый квиз, новые отчёты, журнал и черновики. Баллы остаются под `activitySlug: seminar-4`, максимум — пять. Откат интерфейса не означает удаление данных новой работы.

Пароли, токены, `.env`, `auth.json`, персональные данные студентов, кэши браузеров и файлы шрифтов в ZIP выпуска не включаются.
