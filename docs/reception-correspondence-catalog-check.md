# Проверка частного каталога перед включением «Решения»

Профили `correspondence-v1` собраны из 178 авторских JSON текущего банка: 175 кейсов в 42 учебных семействах и 3 расширения. В профилях зафиксированы 356 вариантов календаря (`a` и `b` для каждого кейса), SHA-256 каждого исходного файла, допустимые жанры документа, предметы обращения, ограничения и авторские контрольные события. Закрытые выводы остаются в Firebase Functions; публичная проекция не передаёт эталонные решения, правильный жанр или ответ на будущий контрольный эпизод.

## Команда допуска каталога

```sh
node scripts/check-reception-correspondence-catalog.mjs --cases /absolute/path/to/existing-private/cases
```

Команда принимает уже подготовленный каталог приватных досье в действующей схеме `validateCase`. Она читает файлы, не создаёт и не изменяет их, не экспортирует новый банк, не запускает `seed`, не обращается к Firebase или модели и не выводит тексты досье. В stdout возвращается JSON с количествами, статусом и кодами ошибок с идентификаторами кейса/варианта. При неполном каталоге, несовпадении SHA-256/версии, неразрешённых датах, ошибке схемы или несовместимой проекции критериев процесс завершается с кодом 1.

Проверяются ровно 178 идентификаторов и все авторские `datePackId`, наличие и соответствие `provenance`, связь дат с зафиксированным вариантом, ссылки профилей на факты/документы/действия, публичная проекция и сборка двух приватных review-контекстов для каждого варианта. Первоначальная проверка получает четыре содержательных критерия; контроль получает отдельные критерии и состояние каждого предмета (`pending`, `resolved`, `referred`). Будущее контрольное событие не включается в первоначальную оценку. Проекция также должна сохранять ограничения роли, маршрутизации и жанра документа.

Для рабочего досье `getCorrespondenceProfile(c)` и публичная проекция возвращают `null` при отсутствии `provenance`, неподдерживаемом `datePackId`, несовпадении исходника или неразрешённых подстановках дат. Это предотвращает выставление оценки по неподтверждённому ключу. Вызов с одним строковым ID предназначен для сборки и инспекции профиля и не является контекстом оценивания. Проверка учитывает два существующих написания календарной политики (`next_working_day` в исходниках и `next_working` в частной схеме); дата при этом не пересчитывается.

## Границы результата

### Полный технический цикл отправки

Для проверки отправки подготовленного снимка всего банка используйте отдельный автономный прогон:

```sh
node scripts/check-reception-bank-submissions.mjs --cases /absolute/path/private-data/cases --out /tmp/reception-bank-submissions.json
```

Он сначала требует успешной проверки состава и происхождения всех 178 дел и 356 вариантов дат. Затем каждый вариант проходит на русском, английском и китайском языках в четырёх сценариях: самостоятельная работа с положительной тестовой оценкой, самостоятельная работа с нулевой тестовой оценкой, обучение и гостевая тренировка. Это 4 272 полных цикла. Проверяются открытие материалов, чат, переключение языка, отправка решения, сбой рецензента, восстановление и повтор с тем же идентификатором, контроль исполнения, завершение и повторное чтение результата. Содержательные поля сохранённого решения и контроля сопоставляются с отправленными значениями. В сценарии нулевой оценки дополнительно используются пустые списки цитат, поручений и контрольных статусов.

Используются настоящий сервис и обработчик ответов провайдера, локальное хранилище с JSON-сериализацией и заранее заданные тестовые ответы модели. Запросы к сети в прогоне запрещены, запись результата направлена в локальную заглушку. Он не обращается к студенческим работам, не записывает оценки в Firebase и не проверяет качество оценивания реальной моделью. Сам снимок частных досье должен оставаться вне `site/` и репозитория.

Отдельная часть того же прогона проверяет каждого допустимого адресата на трёх языках при сборке контекста одного опорного дела. Для текущего каталога это 2 831 адресат и 8 493 контекста, включая региональные органы и прежние обозначения. Это не перебор всех сочетаний «дело × адресат»: в полном цикле каждого дела проверяются его штатный маршрут, выбранный региональный адресат и прежнее обозначение. Ошибка любого сценария или адресата делает весь отчёт `FAIL`; тексты досье, ответов и ключи в отчёт не включаются.

`--smoke N` ограничивает число вариантов для разработки самого теста. Такой результат обозначается `SMOKE_PASS` и не заменяет проверку всего банка. Прогон не запускает тесты других семинаров.

`PASS` относится только к переданному локальному снимку каталога. Даже успешная проверка оставляет `liveFirebaseVerified: false`: загрузка именно этих данных в рабочий Firebase, существующие учебные сессии, секреты и конфигурация развёртывания отдельно здесь не проверяются. На локальном снимке, использованном при интеграции, команда подтвердила 178 дел, 356 вариантов и 712 контекстов проверки без ошибок. Перед включением режима выполните ту же команду над снимком, используемым рабочим Firebase, и сохраните JSON-результат вместе с версией развёртывания.

Проверка устанавливает структурную и содержательную совместимость банка с профилями; она не измеряет надёжность реального LLM-рецензента. Калибровка по работам студентов и экспертной оценке, юридическая актуализация исходного авторского банка и проверка развёрнутого интерфейса остаются отдельными задачами. Профили наследуют правовые основания источников и прямо помечены `independentlyRevalidated: false`; они не подменяют проверку действующего законодательства.

Локальная проверка сборки и контрактов:

```sh
node scripts/build-reception-correspondence-profiles.mjs --check
node --test firebase/functions/reception-ai/correspondence-profiles.test.mjs scripts/check-reception-correspondence-catalog.test.mjs
```

Корпус цитат сверяется с закреплёнными полными текстами встроенной читалки. Команда использует локальные Git-объекты для архивных текстов. Если объектов нет в неглубокой копии репозитория, флаг `--fetch` загружает те же закреплённые архивы и проверяет их SHA-256.

```sh
node scripts/build-reception-correspondence-corpus.mjs --check
```
