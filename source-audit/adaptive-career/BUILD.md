# Воспроизводимость функционального индекса семинара 5

Индекс строится по полному сохранённому банку из 457 627 объявлений и соответствующему обогащённому снимку. Сохранённые дополнительные материалы должностей и небольшой порталовый снимок входят в объединение источников. Отсутствие признака означает, что функция не подтверждена сохранённым текстом; оно не доказывает отсутствия этой функции у работодателя.

## Закреплённые источники

Базовый банк хранится в `source-audit/career-vacancies/seed.json` и перечисленных там двоичных частях. Его SHA256 дерева: `4e0a0659c22cf71830f25ac6772264297a50ad7baf82f9e3f1bd265e6fa19f92`.

Обогащённый источник закреплён файлом `source-audit/career-vacancies/details-hosting.json`: [commit 9bdaea0a82a37516f554c6d68fc3866b8c774ffe](https://github.com/Arseniy24RUS/RUDN/tree/9bdaea0a82a37516f554c6d68fc3866b8c774ffe/career-vacancy-details). Он содержит 15 958 транспортных файлов `.b64`. Декодированный gzip-слой занимает 580 029 763 байта; SHA256 канонического дерева — `8093c0aca170168f46632b72d2af2db44912614798b713345b60bfeb5bd6a17f`. Этот слой не копируется в публичные файлы теста.

Сборщик проверяет полный перечень файлов и digest дерева, затем точное совпадение `baseTreeSHA`, `basePage`, `basePageSHA256`, `employerId` и множества UUID. Для разделённых страниц проверяются также размеры и SHA256 сжатого и распакованного содержимого каждой части. Нечёткое сопоставление названий не используется. Словарь `page-strings-v1` разрешается без изменения исходного текста и его `sourceField`, `sourcePointer`, `sourceNamespace`, `sourceProvenance`.

## Признаки и ограничения

Функциональные признаки извлекаются из конкретных действий и специализированных знаний. Название должности, название подразделения и название работодателя не создают таких признаков. Название должности служит только метаданными и основанием для различения явно указанной руководящей либо неруководящей роли. Неизвестная география сохраняется неизвестной.

Кандидат должен иметь хотя бы одну конкретную подзадачу из банка вопросов. Объявления о группе должностей или кадровом резерве сохраняются в учёте источников, но не превращаются в отдельную конкретную вакансию. Каждый подходящий индивидуальный UUID сохраняется отдельно. Одинаковые функциональные векторы разделяют один профиль, что уменьшает вычисления без объединения разных объявлений.

Текст разбивается по предложениям и границам пунктов. Одиночные переносы строк внутри предложения сохраняются. Явные заголовки требований учитываются: поле с названием `duties` само по себе не доказывает, что записанный в нём текст является обязанностью. Знания должны подтверждать конкретную подзадачу; общие нормы государственной службы, пользовательские ИКТ и универсальные компетенции не считаются специализацией. Дополнительные требования учитываются только при содержательном рабочем действии, а описание конкурсного отбора соискателя исключается.

| Содержание фрагмента | Вес признака |
|---|---:|
| Обязанность | 1,00 |
| Профессиональное умение | 0,85 |
| Рабочее действие в дополнительных требованиях | 0,75 |
| Специализированное знание | 0,45 |

Для каждого признака берётся максимальный подтверждённый вес; повторение текста не увеличивает оценку. Конкретная подзадача подтверждает родительское направление. Отрицания, явно переданные другим сотрудникам задачи и обычное соблюдение требований информационной безопасности исключаются. Пересекающиеся совпадения специфического налогового, таможенного или антимонопольного контроля не создают второй голос общего контроля. Аналогично разграничиваются судебное обеспечение, государственная регистрация и общее делопроизводство; явные межбюджетные трансферты отделены от поддержки организаций.

Начало совпадения проверяется по границе слова: «сведения» не становится «ведением» реестра. Пассивное описание уже выполненной операции не приравнивается к её исполнению сотрудником; при этом пассивное определение объекта внутри действительной обязанности сохраняется. Функция явно названного внешнего органа или адресата запроса не переносится на автора запроса. Отдельно различаются работа с копиями протоколов и их составление, организация отбора и название организаций, учёт имущества и оборот «с учётом». Эти ограничения проверяются на точных исходных текстах и положительных контрольных формулировках в `classification-fixtures.json` и Python-тестах.

Признаки определяются открытыми regex из `adaptive-taxonomy.json`. Ускоряющий фильтр использует только обязательные буквальные фрагменты этих выражений; само выражение и содержательные исключения проверяются после фильтра. Независимые страницы можно обрабатывать параллельно, но результаты поступают в исходном порядке. Число процессов не влияет на итоговые байты.

## Формат файлов

`manifest.json` имеет `schemaVersion: 2`. Кандидаты используют `encoding: career-candidates-dictionary-v1`: строки, работодатели и профили вынесены в словари, а объявления представлены кортежами с фиксированным `columns`. После декодирования сохраняется обычный объект кандидата с общим объектом `features` и `profileId`.

`all.json.gz` служит полным аналитическим индексом. Браузер может получать национальный индекс из `nationalParts` размером до 50 000 строк и 32 MiB распакованного JSON; региональные части содержат только соответствующую географию. Все части проверяются по размерам и SHA256. Подробности разделены на чанки до 100 карточек и загружаются по запросу.

`detail.evidence` содержит дословные выдержки вокруг подтверждённых функций, категорию, идентификатор признака, исходный locator и смещения `sourceTextStart/End`, `matchStart/End`. Смещения выражены в кодовых точках Python относительно полного сохранённого текстового токена; интерфейс использует готовый `sourceText`. Полные тексты доступны в закреплённом исходном слое. Изменённые или пересказанные цитаты не создаются.

`source-members.json.gz` учитывает каждый источник и причину его включения либо исключения. `build-report.json` фиксирует итоговое содержательное покрытие, исходную заполненность полей, контрольные суммы и размеры. Наличие заполненного поля не отождествляется с подтверждённым функциональным содержанием. `enriched-source-audit.json` и `enriched-frequent-source-texts.json` содержат отдельный полный структурный аудит и наиболее частые дословные токены, использованные при разработке правил.

## Проверка

Рабочая среда — Python 3.12. Для полной сборки требуется локальная копия закреплённого обогащённого дерева; сеть во время сборки не используется.

```sh
python scripts/build-adaptive-career-index.py --details-root /absolute/path/RUDN-vacancy-details --workers 4
python scripts/build-adaptive-career-index.py --details-root /absolute/path/RUDN-vacancy-details --workers 4 --check
python scripts/test_adaptive_career_index.py
```

`--check` пересобирает результат во временном каталоге и сравнивает байты всех сгенерированных файлов. Обычные CI-тесты проверяют уже включённый индекс, целостность частей, разбиение по регионам, доказательства признаков, полноту учёта UUID и точные выдержки локальных материалов; скачивать внешний 580 MB слой для них не требуется.

Версия индекса включает fingerprint таксономии, закреплённых источников и самого сборщика. Архивность и сроки отражают сохранённое наблюдение; проверка текущего найма не производится. Результаты психологических тестов в функциональном ранжировании не используются.
