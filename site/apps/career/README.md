# Нативный профориентационный модуль

Модуль версии 1.0.0 встраивается в шестую тему платформы как компонент Shadow DOM. `iframe`, собственная авторизация, отдельный service worker и динамическая компиляция JavaScript не используются. Научная модель, анкета и правила расчёта автономного релиза сохранены: модель и анкета 8.0.0; индекс соответствия не является оценкой успеваемости или пригодности к государственной службе.

## Контракт оболочки

```js
const handle = await mountCareer(container, {
  owner: attemptOwner(),
  lang: 'ru',
  initialRoute: 'home',
  signal: abortController.signal,
  onRouteChange(route, { replace }) { /* router платформы */ },
  onResult(record) { /* локальное уведомление, без автоматической оценки */ }
});
handle.navigate('methodology');
await handle.setLocale('en');
handle.destroy();
```

`owner` — строка владельца из платформы. Черновик ответов, сценарии, рабочая тетрадь и настройки языка разделены по владельцу и каталогу установки. Гостевой владелец имеет отдельное пространство. Модуль не читает общие ключи автономных старых версий и не передаёт ответы чужому профилю. Эта изоляция интерфейса не заменяет авторизацию платформы и не является шифрованием localStorage.

`onResult` получает существующий закрытый формат `rudn-career-result` версии схемы 2: `recordId`, `createdAt`, версии модели/анкеты/реестра, профиль девяти шкал, предпочтения, условия и вычисленный рейтинг. Поля имени, электронной почты, UID и оценки отсутствуют. Идентификатор сохраняется при повторном открытии результата. В пределах одного mount callback вызывается один раз для этого идентификатора; после нового mount тот же результат может быть сообщён повторно. Изменение ответов аннулирует прежний идентификатор.

Внутренняя навигация передаётся `onRouteChange`; `navigate` не вызывает обратный callback и не изменяет глобальные URL/history. Встроенная локализация изменяет только корень компонента. `signal` позволяет отменить загрузку до завершения `mountCareer`; `destroy` отключает слушателей и наблюдателей, отменяет запросы и таймеры и освобождает временные URL файлов.

## Файлы и сборка

`entry.mjs` предоставляет жизненный цикл и ограниченные браузерные возможности. `assets/` содержит адаптированные исходники автономной версии. `runtime.bundle.mjs` — статическая factory-сборка: каждый вызов создаёт собственное состояние. `surface.html` сохраняет структуру приложения без второй брендовой шапки. `module.css` изолирован Shadow DOM; адаптивность определяется шириной контейнера курса. Данные и локали находятся в `data/` и `locales/`.

Из корня репозитория сборка воспроизводится командой `node scripts/build-career.mjs` с уже используемой зависимостью esbuild. Изменения адаптера в `entry.mjs` и поверхности в `surface.html` применяются напрямую; после изменения исходного JavaScript или CSS следует пересобрать runtime и stylesheet.

Внешний портал вакансий работает через официальные ссылки и сохранённый информационный снимок. Живой административный API в публикации GitHub Pages не вызывается. Сохранение и расчёт теста работают независимо от источника вакансий. Общим офлайн-кэшем управляет service worker образовательной платформы.

## Проверка адаптера

Локальная проверка выполнялась в реальном Chromium с HTTP-сервера и исходными файлами модуля. Проверены ручной ввод всех 27 ответов, расчёт и callback, досье, сравнение, сценарии, чувствительность модели, профессиональная проба и рабочая тетрадь; переключение владельца A → B → A; переключение языка без изменения оболочки; завершение и отмена жизненного цикла. Адаптивная проверка охватывала ширины 320, 390, 768 и 1440 пикселей. Физические мобильные устройства, Safari и Firefox в этой проверке не использовались.

Доступность и совместная работа с реальной оболочкой проверяются отдельно при интеграции платформы. Психометрическая валидация модели не подменяется техническими проверками интерфейса.
