# Советник семинара 7

Firebase Function `governorV3Advisor` принимает только JSON POST с проверенным Firebase ID token. Поддерживается origin опубликованной платформы. Loopback разрешён в тестовом проекте `demo-*` при локальных Auth и RTDB. Сервер сверяет канонический учебный профиль и UID. Привязка случайного ID попытки к тому же владельцу проверяется при каждом обращении. Гостевая локальная справка не требует вызова функции.

На вход поступают `requestId`, `attemptId`, `studentKey`, `year`, `revision`, `language`, `question` и `facts`. В `facts` разрешены денежные поля текущего бюджета, три налоговых варианта, проверяемые численные сведения о разрешённых площадках и один маршрут. Лишние поля отклоняются. Сервер отправляет модели численные игровые сведения и совпавшие слова из игрового справочника. Исходный текст, профиль, ключи жеребьёвки и сведения о других попытках в запрос модели не входят.

Ответ состоит из одного `intent` из ряда `tax`, `sites`, `loan`, `budget`, `route`, `compare`, `unknown`. Числа и переходы строятся клиентом по фактическому сохранённому состоянию. Код `409` означает параллельный запрос или конфликт повторного идентификатора. После закрытия повтор возвращает тот же ответ. Ошибка при ожидании ответа провайдера завершает этот идентификатор и исключает повторный вызов.

Закрытая область RTDB находится по пути `rudn-platform/v1/governorV3Advisor`. Она содержит хэш владельца, хэши идентификаторов, отметки времени, этап запроса и перечислимый ответ. Полный текст и численные сведения не сохраняются. Верхние пределы составляют 50 обращений на попытку, 16 на UID в день и 240 на проект в день. Прерванный запрос может остаться в состоянии ожидания. Его повтор использует локальную подсказку при получении `409`. Учебная запись и состояние партии обрабатываются отдельным штатным контуром.

Провайдер включается только при `GOVERNOR_V3_ADVISOR_ENABLED=true`, явно заданном `GOVERNOR_V3_ADVISOR_MODEL` и серверном секрете `RUDN_GOVERNOR_V3_OPENAI_KEY`. Положительное включение и модель администратор задаёт при выпуске. Упражнения и проверки работают с локальным советником и в отсутствие этой конфигурации. Проверок с действующим ключом в локальном прогоне не проводится.

Модульные тесты из корня репозитория запускаются командой `node --test firebase/functions/governor-v3-advisor/advisor.test.mjs`. Интеграционный тест `emulator-check.mjs` запускается с локальными Auth, RTDB и Functions для `demo-governor-v3`, переменной `GOVERNOR_V3_ADVISOR_MOCK=true` и локальным URL функции в `GOVERNOR_V3_EMULATOR_URL`. Профили и запросы тестовые. Тест проверяет CORS, токен, привязку владельца, один учтённый вызов при параллельной отправке и запрет прямого чтения приватного хранилища.
